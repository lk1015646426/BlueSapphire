# 清理助手 P0 安全收口设计
> 历史设计记录：本文件描述 2026-07-19 的 P0 范围。2026-07-22 的实际执行、依赖闭包和验证结果见 `docs/superpowers/plans/2026-07-19-cleaner-p0-safety.md`、`docs/cleaner-functional-audit.md` 与 `docs/cleaner-workflow-acceptance.md`。

## 目标

修复全检确认的四个 P0 问题：自动保洁不可逆删除、多个入口并发执行磁盘操作、取消后文件状态与历史不一致、Debug 测试覆盖项目资源文件。

## 已确认的产品行为

1. 自动保洁只处理低风险、默认选中、当前可执行且可恢复的隔离区或回收站项目。永久删除和 Windows 系统动作只能进入人工核对流程。
2. 快速扫描、深度扫描、手动清理、自动保洁、失败重试、恢复、隔离区清空以及 AI 扫描/清理共享同一个操作协调器。协调器同时阻止同一进程内和同一 Windows 会话内的第二个程序实例执行磁盘主操作。
3. 恢复、清空隔离区和失败重试中途取消时，已经完成的条目必须在抛出取消异常前写入历史；未开始的条目保持原状态。
4. 运行时数据只写 LocalAppData 或测试指定目录。任何 Debug 构建和测试都不得反向覆盖 `Assets/DevMatrixLog.json`。

## 架构

- 新增 `CleanerOperationCoordinator`，以会话级命名 `Semaphore` 实现跨进程互斥，以内存状态和事件同步当前进程 UI。它只管理主操作所有权，不承担扫描或删除策略。
- UI 扫描 ViewModel、清理/恢复 ViewModel、自动保洁编排和 AI 动作在进入服务前申请租约，并在历史、审计和可见状态完成后释放。
- 自动保洁持有一个覆盖“扫描 → 筛选 → 执行 → 历史/审计”的租约；其内部扫描使用显式的既有租约入口，避免隐式可重入。
- `CleanerExecutionService` 在取消捕获路径持久化部分完成结果。恢复和隔离区清空增加进度重载，用于确定性的取消测试和后续 UI 反馈。
- 删除 `DevLogDataService` 的项目目录反向同步逻辑，并增加源代码不变量测试。

## 失败与取消语义

- 申请不到操作租约时不排队执行磁盘动作；UI/AI 返回“清理助手正在执行另一项任务”。
- 自动保洁发现永久删除候选时保留候选文件，不把它计入本轮自动处理。
- 取消恢复、清空或重试时仍抛出 `OperationCanceledException`，但已成功变更的条目先落盘。
- 协调器租约必须在 `finally`/`using` 中释放，异常不能永久锁死后续操作。

## 验收切片

| 用户/系统动作 | 可见或持久状态 | 所有者 | 自动化证明 |
|---|---|---|---|
| 自动保洁同时发现隔离和永久项 | 只移动隔离项，永久项保留 | `CleanerAssistantViewModel` | 真实临时文件测试 |
| AI 扫描期间用户点击扫描 | 第二个入口拒绝，首个租约仍有效 | `CleanerOperationCoordinator` | 两个协调器实例共享命名门禁 |
| 恢复/清空/重试完成首项后取消 | 首项状态保存，后续项不被伪装为完成 | `CleanerExecutionService` | 每类取消回归测试 |
| Debug 测试保存开发日志 | 项目 `Assets` 内容不变化 | `DevLogDataService` | 源码不变量 + 完整 Debug 测试 |

## 非目标

本阶段不处理深度扫描盘符传递、旧批次恢复 UI、执行并发度、AI 日志脱敏和整体视觉重构；这些属于随后 P1/P2。

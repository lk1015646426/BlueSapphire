# BlueSapphire 暖陶浅色 UI 美化设计规格

日期：2026-08-22  
状态：已获用户确认，等待规格文件审阅  
适用版本：BlueSapphire 1.0.3

## 1. 目标

在保留当前“暖陶浅色”品牌方向和现有 WinUI 3 导航壳的前提下，将 BlueSapphire 从“多个卡片堆叠的工具集合”调整为更专业、克制、层级清晰的 Windows 桌面工具界面。

本轮优先解决影响观感和使用效率的结构问题：页面层级、主操作识别、表面层次、间距节奏、按钮一致性和空状态引导。

## 2. 非目标

- 不替换 WinUI 3、Windows App SDK 或现有导航壳。
- 不新增 UI 框架、组件库或其他依赖。
- 不改变扫描、清理、删除、恢复、媒体处理、AI 确认和任务中心的业务语义。
- 不删除现有浅色、深色、高对比度和主题预设能力。
- 不顺便进行架构重构、数据模型修改或无关代码清理。
- 第一批不超过 5 个实现文件。

## 3. 设计基线

### 3.1 视觉性格

- 背景使用暖白、浅米色和低对比度暖灰表面。
- 陶橙色只作为主要信号色，服务于主按钮、当前选中态和关键状态。
- 保留轻微圆角和细边框，但避免厚阴影、强渐变和装饰性光效。
- 使用 Segoe UI Variable / Segoe UI 为统一 UI 字体，中文回退到 Microsoft YaHei UI。
- 通过留白、字重和标题层级建立分组，减少“框中框”。

### 3.2 表面层级

统一为三层：

1. 应用背景：页面底色和导航底色。
2. 页面主内容面：承载一个完整任务或工作台。
3. 重点表面：只用于需要强调的输入区、结果区、说明区或确认区。

普通分组优先使用间距、标题和分隔线，不再为每个小区块新增外层 `Border`。

### 3.3 操作层级

每个页面只保留一个最重要的主操作：

- 首页：开始 AI 工作或进入清理工具。
- 清理工具：开始扫描。
- 媒体管家：导入图片文件夹。

次要操作使用次按钮、文字按钮或图标按钮。图标按钮必须有 Tooltip、AutomationProperties.Name 和清晰的焦点状态。

## 4. 页面设计

### 4.1 应用外壳

文件：`MainWindow.xaml`

- 保留 `NavigationView` 和现有页面导航。
- 导航栏使用略暖于主背景的独立表面，选中项使用窄陶橙色指示条和低透明度填充。
- 标题栏保持简洁，避免与页面标题重复竞争。
- 宽窗口保持展开导航，窄窗口使用紧凑导航；不改变现有导航行为。

### 4.2 主页

文件：`Views/HomePage.xaml`

- 将 AI 助手区域从“大面积聊天卡片”调整为紧凑的工作入口。
- 让输入框、连接状态和发送动作形成明确的第一操作区。
- 任务和最近活动作为下方工作摘要，使用清晰的区块标题和少量分隔线。
- 空状态必须告诉用户下一步，而不是只显示“暂无内容”。
- 宽窗口使用任务/活动双列；窄窗口改为单列，活动区降级到任务区之后。

### 4.3 清理工具

文件：`Views/CleanerAssistantPage.xaml`

- 保留“清理 / 自动化与规则 / 记录”的页内导航，但降低其视觉重量。
- 将扫描范围、扫描说明和主内容建立明确的左主区 / 右说明区关系。
- 减少扫描卡片、磁盘行、说明卡片之间的重复边框。
- “开始快速扫描”成为页面最明显的主按钮。
- 扫描结果、风险等级和安全说明继续保留现有语义，不改变确认逻辑。
- 窄窗口时右侧说明区移动到主内容之后，避免横向挤压。

### 4.4 媒体管家

文件：`Views/MediaManagerPage.xaml`

- 顶部搜索、标签筛选和导入动作形成单一工作栏。
- 空状态突出“导入图片文件夹”，并保留一句简短解释。
- 将次要筛选和排序操作降级，避免与主导入动作竞争。
- 保留现有媒体处理能力和数据绑定方式，不改变导入流程。

## 5. 第一批实现文件

第一批只修改以下 5 个文件：

1. `Themes/SharedTheme.xaml`
2. `MainWindow.xaml`
3. `Views/HomePage.xaml`
4. `Views/CleanerAssistantPage.xaml`
5. `Views/MediaManagerPage.xaml`

设置页、AI 对话页、弹窗和主题选择器属于第二批，必须在第一批完成并验证后单独评估。

## 6. 响应式与可访问性

- 保持浅色、深色和高对比度主题可用，颜色全部通过主题资源获取。
- 关键文本与背景满足可读性要求；不使用过淡的辅助文字作为唯一信息载体。
- 所有主操作保留键盘焦点可见状态。
- 最小交互尺寸不因视觉收紧而低于当前 WinUI 可用范围。
- 宽窗口、窄窗口至少各验证一次；窄窗口不允许主按钮、说明文本或列表内容被截断。
- 动效仅用于状态变化和页面进入；不增加持续装饰动画。

## 7. 验收标准

- 首页、清理工具和媒体管家使用统一的标题、按钮、边框、间距和表面语言。
- 每个页面的主操作可在首屏快速识别。
- 第一批页面的嵌套卡片和重复边框明显减少。
- 空状态明确告诉用户下一步。
- 浅色和深色主题都能正常显示，且不出现硬编码的单主题颜色。
- 关键操作的焦点、禁用、加载和错误状态不被破坏。
- `dotnet build BlueSapphire.slnx --no-incremental` 退出码为 0，警告为 0，错误为 0。
- `dotnet test BlueSapphire.Tests/BlueSapphire.Tests.csproj` 退出码为 0。
- 启动实际构建的应用，确认顶层窗口出现并检查首页、清理工具、媒体管家三个页面。
- 执行 `git diff --check`，无空白错误。

## 8. 风险与回滚

- 风险：共享主题令牌被多个页面依赖，修改时可能造成局部页面对比度或尺寸变化。
  - 控制：先调整共享令牌，再逐页验证；不删除旧令牌，只在必要时新增语义别名。
- 风险：清理工具页面信息密度高，减少边框可能降低分组辨识度。
  - 控制：使用标题、间距和分隔线补足层级，不直接删除安全说明和风险提示。
- 风险：窄窗口下的页内布局可能出现横向挤压。
  - 控制：保留并补充现有 VisualState / SizeChanged 逻辑，只调整视觉和布局组合。

回滚方式：第一批改动限定在上述 5 个文件，任何页面验证失败时可按文件粒度回退，不影响业务逻辑、数据文件和安全边界。

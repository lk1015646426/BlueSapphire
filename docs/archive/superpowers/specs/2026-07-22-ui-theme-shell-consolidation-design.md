## 4. 设计原则

### 4.1 产品界面定位

BlueSapphire 是长期使用的 Windows 工具工作台。设计服务于任务：

- 用户应首先看到当前任务、状态、风险、影响和下一步；
- 熟悉的 Windows 控件优先于自造交互；
- 一致性优先于视觉惊喜；
- 密度可以较高，但层级必须清楚；
- 空状态必须说明当前状态和可执行动作。

### 4.2 视觉语言

- 字体统一使用 Segoe UI Variable / Segoe UI。
- 标题层级紧凑，避免展示型大标题。
- 采用细边框、6–10px 圆角和平面表面层级。
- 主色只用于主要动作、当前选择、焦点和实时状态。
- 成功、复核、查看和危险颜色仅用于对应语义。
- 不依赖阴影建立主要层级，不使用无业务意义辉光。
- 默认主题保持暖陶色品牌方向，不替换为通用模板配色。

### 4.3 动效

- 常规状态转换控制在 150–250ms。
- 进入使用 ease-out，退出使用更快的 ease-in。
- 动效只表达加载、状态切换、反馈和内容显隐。
- 不做编排式页面入场或多卡片连续表演。
- “减少动态效果”开启后，非必要 Storyboard、缩放和位移动画停止；内容直接进入最终状态。

## 5. 主题架构

### 5.1 `Themes/SharedTheme.xaml`

作为 XAML 设计令牌和控件样式的权威来源，负责：

- 背景、侧栏、面板、边框和浮层画刷；
- 主色及悬停、按下、弱背景状态；
- 成功、复核、查看和危险语义色；
- 正文、次要、静音和反色文字；
- 按钮、列表、卡片、设置项、输入框和对话框样式；
- 标题、正文、说明、标签和指标排版样式；
- WinUI 原生选择、焦点和强调色映射。

页面不得再建立独立调色板。兼容别名可以保留，但新页面优先使用语义名称。

### 5.2 `App.xaml.cs`

负责运行时主题状态：

- `Light`、`Dark`、`System` 颜色模式；
- 默认暖陶、天蓝、钴蓝、石墨、泻湖、墨色、赭橙、棕褐主题预设；
- 小、标准、中、大字号资源；
- 本地设置持久化；
- 高对比度时使用系统语义色或安全回退；
- 动态更新 Application Resources，不要求重启页面。

`App.xaml.cs` 不再负责页面级视觉结构。

## 6. 应用外壳

### 6.1 导航

主要导航区：

- 工作台；
- 媒体工作台；
- 清理工具。

左下固定区：

- 更新日志；
- 主题切换；
- 设置。

外壳必须保持：

- 当前页面选中状态明确；
- 窄窗口收起文字但保留图标和自动化名称；
- 键盘、鼠标和触控均可访问；
- 页面切换不重建长任务服务；
- 导航项删除后不保留失效 tag 或类型引用。

### 6.2 标题栏与材质

- 优先使用 Windows App SDK 支持的标题栏和背景材质。
- Acrylic/Mica 初始化失败时回退到主题背景画刷。
- 不因为材质失败阻止窗口启动。
- 标题栏按钮颜色在浅色、深色和高对比度下保持可见。

### 6.3 窗口生命周期

- 关闭窗口不得同步等待 UI 线程。
- 导航和设置事件在窗口关闭时解除订阅。
- 主题、字号和减少动态效果变更不创建重复事件处理器。
- 窗口恢复、再次启动和普通关闭都必须通过真实进程验证。

## 7. 页面设计

### 7.1 设置页

设置页负责外观、AI 服务和扩展连接：

- 分区清晰，避免所有设置堆在单一卡片；
- 主题预设使用单选语义；
- 颜色模式、字号、减少动态效果保存后立即反馈；
- API 模型、MCP 和 Skill 操作展示加载、成功和失败状态；
- 表单在失焦或提交时给出明确校验；
- 大字号下不裁切说明或主要按钮。

### 7.2 媒体工作台

- 紧凑工具栏、素材区、批处理和详情区使用统一令牌；
- 搜索和本地筛选即时更新，远程或昂贵操作保留明确执行入口；
- 集合滚动所有权明确，不嵌套冲突的纵向滚动区域；
- 窄窗口减少次要信息，主要导入、筛选和处理动作保持可达；
- 不改变媒体业务算法。

### 7.3 更新日志

- 列表和详情层级紧凑；
- 新增/编辑使用统一工作台对话框；
- Markdown 链接和文本颜色使用主题资源；
- 删除、编辑后焦点回到合理位置；
- 正式历史保护继续由第一阶段机制保证。

## 8. 对话框

范围：

- 重命名预览；
- 重复文件结果；
- 格式转换；
- 自动增强；
- 高级图像编辑；
- Skill 网络配置；
- 更新日志输入。

统一规则：

- 标题说明任务，不使用装饰副标题；
- 主要动作在右侧，取消/关闭保持一致；
- 危险动作说明范围、不可逆性和恢复方式；
- 长任务有加载和取消状态；
- 空列表说明下一步；
- 图标按钮有 `AutomationProperties.Name`；
- 对话框关闭后恢复调用方焦点；
- 不额外包裹无作用的双层 Border。

## 9. 响应式与可访问性

### 9.1 支持尺寸

- 1600×900：完整高密度布局；
- 1280×800：主要支持尺寸，不裁切核心动作；
- 窄窗口：导航收起、复杂列布局改为单列或隐藏次要区域；
- 大字号：主要按钮、标签和说明不重叠。

使用 `VisualStateManager`、`AdaptiveTrigger` 或等价布局状态，不依赖固定单一宽度。

### 9.2 可访问性

- 正文和关键控件对比度至少 4.5:1；
- 焦点状态清晰，不只依赖颜色；
- 主要操作支持 Tab 导航；
- 图标按钮和选择项有自动化名称；
- 状态同时使用文字/图标和颜色；
- 减少动态效果可用；
- 高对比度使用系统或安全回退资源。

## 11. 依赖闭包验证

每个切片提交前：

1. 只暂存明确文件，不使用 `git add .`。
2. 从当前 `HEAD` 创建短路径临时工作树。
3. 只应用 staged patch。
4. 运行 restore、全量测试和无增量构建。
5. XAML 编译错误只根据明确资源、命名元素、事件处理器或类型依赖扩大闭包。
6. 混合文件从 `HEAD` 构造最小候选，暂存后恢复主工作树内容。
7. 成功后移除临时工作树并形成提交。

主题资源闭包必须额外验证：

- 当前页面引用的所有 `StaticResource` / `ThemeResource` 在提交快照中存在；
- 不存在循环别名；
- 浅色、深色和高对比度有安全值；
- 控件样式不依赖未提交页面资源。

## 13. 失败与回滚

- 如果完整主题导致多个页面资源缺失，先修复共享令牌，不在每个页面复制画刷。
- 如果三个连续修复暴露不同的资源所有权问题，停止补丁并重新讨论主题字典结构。
- 如果外壳切片依赖设置页事件，按编译证据合并 A/B，不提交半套消息协议。
- 如果对话框视觉改动改变业务参数或算法，回退业务改动，只保留视觉和交互状态。
- 如果材质初始化失败，使用普通主题背景，不阻止窗口启动。
- 所有回滚只作用于当前 UI 切片，不覆盖前三阶段提交或其他用户数据。
